# NR Nexus v0.4.0 — 自适应分辨率与运动衰减 / Adaptive resolution and motion attenuation

<!-- Previous: v0.3.0 -->

## 简体中文

### 版本亮点

设定目标帧率，让插件自动调整 NR 工作分辨率；运动衰减可在快速运动区域减少 NR。顶栏统一显示帧率、NR GPU、帧生成和当前 NR 分辨率，并改善自动模式下的介入点切换与运行状态显示。

### 新增功能与改进

- **自适应分辨率**：在核心画质中开启，设置目标输出 FPS 和最低相对比例。默认 60 FPS／67%，范围为 30–360 FPS／33–100%；可直接输入精确目标，例如 116。目标包含生成帧，统计或估算由插件完成，无需另装帧率程序。
- 各层保存的手动尺寸作为自动上限；自动模式下尺寸和比例显示只读的实际值，关闭后恢复手动编辑。降低尺寸有收益时保留较低档，收益不明确时恢复较高画质。
- 在既有缓存和显存预算内准备可用档位，完成准备后再切入；兼容的原生 DX12 单阶段链支持自动调节，包括 XeFG／原生 FG 同尺寸路径。
- **运动衰减**：在区域遮罩设置内开启，按运动矢量减少 NR 应用量，可与深度衰减联用。默认关闭，淡出起点／终点为 16／160 像素／帧，支持逐层继承或独立设置；自动调节尺寸时保持参考尺度一致。
- 顶栏采用标题在上、数值在下的紧凑布局，随宽度换行；“NR 分辨率”显示当前实际比例，数值来源、倍率和尺寸基准放在悬停提示中。移除重复状态行和预计工作分辨率。

### 修复内容

- 修复部分区域遮罩切换或已有资源历史导致 NR 无法继续执行的问题。
- 修复自动模式下介入点按钮无法切换，以及准备等待被误报为执行失败并永久暂停的问题。
- 修复超分后、渲染介入点下档位一直准备，导致自动分辨率无法调节的问题。
- 完善最低比例、轮换输出和实际档位变化后的缓存兼容性、资源回收及帧率跟踪。
- 改善近期 GPU 结果的状态保留，修复多线程采样和重复调用记账造成的“正在检查 NR”误提示。
- 隔离着色器构建输入，改善切换构建根目录后的缓存重建。

### 验证情况

功能候选在《巫师 3》DX12／XeFG 4× 完成定向静态实机检查，覆盖介入点切换、双 Pass 自适应启用、实际尺寸变化和持续状态观察。用户随后完成动态测试，反馈没有明显问题。其他游戏与组合仍按玩家指南的支持范围使用。

受影响部分的 CPU、WARP／MOCK、硬件 GPU 与原生 NGX 定向证据分别保留；最近的状态／UI 回归 1625 项及健康状态检查 41 项通过。Release 构建、多语言与选定中英文 UI 预览通过。v0.4.0 发行构建由 Tag 工作流执行构建、自动测试、PE 版本和打包检查，最终附件核对源码、包内容和 SHA-256。本轮发布准备只更新版本与文档，复用上述功能验收，不额外启动游戏。

### 已知限制

- 首次开启或模型、游戏尺寸改变后需要准备档位，可能短暂停顿并增加显存使用。已测准备调用约有 54–187 毫秒 CPU 开销；这与已就绪档位的切换耗时不同。
- 调节采用离散档位。颜色、输出数量和缓存预算会限制可用档数；部分场景仍可能感到画质变化，可提高最低比例减小差异。
- 仍可能有极短的“部分运行”状态闪动；本轮静态记录到一次约 11 毫秒的变化，期间 NR 持续执行。
- 自动分辨率当前面向原生 DX12 单阶段；跨阶段、FG 异尺寸、DX11 Bridge 和 Vulkan 继续使用手动尺寸。缺少可靠帧率来源时暂停自动；动态 FG 信息不足时暂停质量试探。限帧、CPU 瓶颈或其他负载可能使目标无法达到。
- 运动衰减同时响应相机和物体运动，不作语义区分；缺少有效输入时跳过相应自动规则。历史遮罩挂起报告仍未确定原因，定向复验未复现；若再次发生，请保留日志。

### 安装说明

下载 Windows x64 ZIP 与对应的 `.zip.sha256` 并校验。关闭游戏，备份插件及设置，只替换 `renodx-dlss5.addon64`，避免重复加载并保留许可文件。另行准备支持完整 Add-on／API 18 的 ReShade 和合法取得的兼容 `nvngx_dlssnr.dll`；安装包不附带厂商 Runtime、模型、SDK 或 ReShade 加载器，内含中英文离线玩家手册。

## English

### Highlights

Set a target frame rate and let the add-on adjust NR working resolution. Motion attenuation reduces NR in fast-moving regions. The compact summary shows FPS, NR GPU, frame generation and current NR resolution, with improved hook-point switching and status reporting in automatic mode.

### Features & Improvements

- **Adaptive resolution**: Enable it in Core quality and set target output FPS and minimum relative scale. Defaults are 60 FPS / 67%, with ranges of 30–360 FPS / 33–100%. Enter an exact target such as 116. Generated frames count toward the target; measurement or estimation runs inside the add-on without an extra FPS program.
- Each pass's saved manual size is its automatic upper limit. Automatic mode shows read-only actual size and scale; turning it off restores manual editing. Lower levels are kept when they help, and higher quality is restored when the benefit is unclear.
- Prepare available levels within existing cache and video-memory budgets, then select ready levels. Compatible native DX12 single-stage chains support automatic sizing, including same-size XeFG / native FG paths.
- **Motion attenuation**: Enable it in Region mask settings to reduce NR intensity using motion vectors, optionally together with depth fading. It is off by default, with fade start / end at 16 / 160 pixels per frame and per-pass inheritance or independent settings. Adaptive sizing preserves the reference scale.
- Summary labels sit above values and wrap with panel width. NR resolution shows the actual current scale; sources, multiplier calculations and size references are on hover. Duplicate status text and estimated working-size rows have been removed.

### Fixes

- Fixed some region-mask changes or existing resource history preventing NR from continuing.
- Fixed hook-point buttons failing to switch in automatic mode, and preparation waits being misreported as execution failures that permanently paused automatic sizing.
- Fixed level preparation waiting indefinitely on Upscaled and Render, preventing automatic sizing from adjusting resolution.
- Improved cache compatibility, resource cleanup and frame-rate tracking when minimum scale, rotating outputs or actual levels change.
- Improved retention of recent GPU results and fixed multithreaded sampling and duplicate-call accounting causing false Checking NR messages.
- Isolated shader build inputs and improved cache rebuilds when changing build roots.

### Validation

The functional candidate completed targeted static in-game checks in The Witcher 3 DX12 / XeFG 4×, covering hook-point switching, two-pass adaptive activation, actual size changes and sustained status observation. The user subsequently completed dynamic testing and reported no significant issues. Use other games and combinations within the User Guide's documented scope.

Targeted CPU, WARP / MOCK, hardware GPU and native NGX evidence is retained within each affected path's scope. The latest status/UI regression passed 1625 checks, with another 41 health-state checks passing. Release builds, language checks and selected English/Chinese UI previews passed. The v0.4.0 tag workflow runs the build, automated tests, PE version and packaging checks; final assets are checked against source, contents and SHA-256. This release preparation changes version metadata and documentation only, reusing functional acceptance without launching another game.

### Known Limitations

- First activation or a model/game-size change requires level preparation, which can briefly pause rendering and increase video-memory use. Measured preparation calls used roughly 54–187 milliseconds of CPU time; this differs from switching between ready levels.
- Sizing uses discrete levels. Color count, outputs and cache budgets limit the available levels; some scenes can still show quality changes. Raising the minimum scale reduces the differences.
- Very brief Partly running status flashes remain possible. One roughly 11-millisecond transition was recorded in the latest static test while NR continued executing.
- Automatic sizing currently targets native DX12 single-stage paths. Cross-stage chains, different-sized FG chains, DX11 Bridge and Vulkan retain manual sizing. It pauses without reliable frame-rate data; insufficient dynamic FG data pauses quality trials. Frame caps, CPU limits or other workloads can prevent reaching the target.
- Motion attenuation responds to both camera and object movement without semantic distinction. Missing inputs skip the corresponding automatic rule. An earlier mask-related hang report remains unexplained and was not reproduced in targeted retesting; retain logs if it recurs.

### Installation

Download and verify the Windows x64 ZIP and matching `.zip.sha256`. Close the game, back up the add-on/settings, replace only `renodx-dlss5.addon64`, avoid duplicate active copies and keep the licenses. Supply ReShade with full add-on/API 18 support and a legally obtained compatible `nvngx_dlssnr.dll` separately. Vendor runtimes, models, SDKs and the ReShade loader are not bundled. A bilingual offline player guide is included.
