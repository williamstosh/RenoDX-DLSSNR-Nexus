# NR Nexus v0.2.0-dev.9 — Per-pass Working Resolution / 逐层工作分辨率

## 简体中文

### 版本亮点

第 2–4 层现在可分别选择工作分辨率模式与比例。原生 DX11／DX12 支持跨 StageGroup 的不同尺寸，以及受限的同组双 Pass 不同尺寸；普通 Present 双 Pass 还要求成功的进程级公共 FG Off 声明。

### 新增功能与改进

- 新增六个逐层预设字段，默认继承全局分辨率设置；可跟随有效游戏 Guide，或按本 Stage 完整尺寸使用固定比例。Schema 1 不变，旧预设缺少新字段时保持现有值。
- 支持原生 DX11 Bridge／DX12 的跨 StageGroup 分辨率覆盖；在不含 Present 的链中，Render 或 Upscaled StageGroup 的恰好两个 Pass 可用不同工作尺寸。
- 普通原生 DX11 Bridge／DX12 Present 仅允许恰好两个 Pass 使用不同尺寸，并要求收到成功的进程级 FG Off 声明。FG 状态未知／开启、Pre-FG、B1／混合链继续拒绝；Vulkan 明确拒绝独立分辨率模式。
- 同组三层以上仍要求实际工作尺寸一致。DX11 Present 双 Pass 沿用 GPU 完成证明并增加有界同步等待；尺寸组合不受支持时保留设置并跳过该组。
- 逐层设置已同步到方案导入／导出、撤销、六个配置 Slot、UI 诊断及 14 种语言。

### 验证情况

原生 DX11 Bridge 与 DX12 的受影响 WARP／RTX 5090 D 定向 GPU 自动化通过，覆盖跨阶段组、Render／Upscaled 双 Pass、Present 双 Pass、两个尺寸方向、HDR 代表格式、逐层 GPU 标记读回、尾层尺寸变化、History、失败恢复、资源退休及 FG Off 门控。配置、方案和导入／撤销回归通过。Release 构建、dev.9 PE 品牌／版本、15 语言 branding 与文档差异检查通过。测试使用确定性 NR／SR 替身，不证明 NVIDIA 网络身份或真实游戏行为。

### 已知限制

真实游戏入口、NVIDIA 网络、画质、长时稳定性及可归因性能收益未验收。Present 双 Pass 必须先收到成功的进程级公共 FG Off 声明；未收到、失败或 FG 已开启时继续拒绝。Vulkan 逐层独立分辨率和同组三层以上不同尺寸不支持。B2／P2-C 仍为 BLOCKED，B3 仍为 NO-GO。

### 安装说明

发布后，从本项目 Releases 下载 v0.2.0-dev.9 Windows x64 ZIP 并核对 `.zip.sha256`。关闭游戏并备份现有插件与设置后，仅替换 `renodx-dlss5.addon64`，保留包内说明和许可。另需支持完整 Add-on／API 18 的 ReShade 与合法取得的兼容 NVIDIA `nvngx_dlssnr.dll`；A/B 模型要求识别到 310.9.16.0。

## English

### Highlights

Passes 2–4 can now choose their working-resolution mode and scale independently. Native DX11/DX12 supports different sizes across StageGroups and limited two-pass same-group cases. Ordinary Present pairs also require a successful process-wide public FG Off declaration.

### Features & Improvements

- Added six per-pass preset fields that inherit the global resolution settings by default. A pass can follow a valid game guide or use a fixed scale relative to its Stage's full reference size. Schema 1 is unchanged; older presets missing these fields retain current values.
- Added working-resolution overrides across StageGroups on native DX11 Bridge/DX12. In a chain without Present, exactly two passes in a Render or Upscaled StageGroup can use different working sizes.
- Exactly two ordinary native DX11 Bridge/DX12 Present passes may use different sizes after a successful process-wide FG Off declaration. Unknown/on FG, Pre-FG and B1/mixed chains remain rejected; Vulkan explicitly rejects independent-resolution modes.
- Groups of three or more passes still require matching actual sizes. The DX11 Present pair reuses GPU-completion proof and adds a bounded synchronization wait; unsupported combinations retain their settings and skip the group.
- Per-pass settings are integrated with preset import/export, undo, all six configuration Slots, UI diagnostics and 14 languages.

### Validation

Affected WARP/RTX 5090 D targeted GPU automation passed for native DX11 Bridge and DX12. Coverage includes cross-StageGroup, Render/Upscaled pairs, Present pairs, both size directions, representative HDR formats, per-pass GPU-marker readback, tail-only size changes, History, failure recovery, resource retirement and FG Off gating. Configuration, preset and import/undo regressions passed. The Release build, dev.9 PE brand/version, 15-language branding and documentation diff checks passed. Tests use deterministic NR/SR substitutes and do not establish NVIDIA network identity or actual game behavior.

### Known Limitations

Actual game entry points, the NVIDIA network, image quality, long-session stability and attributable performance gains remain unverified. Present pairs require a successful process-wide public FG Off declaration and remain rejected when the declaration is absent, fails or FG is on. Vulkan per-pass independent resolution and different sizes across groups of three or more passes are unsupported. B2/P2-C remain BLOCKED and B3 remains NO-GO.

### Installation

After publication, download the v0.2.0-dev.9 Windows x64 ZIP from this project's Releases and verify `.zip.sha256`. Close the game and back up the current add-on and settings, then replace only `renodx-dlss5.addon64`; keep the included documentation and license notices. ReShade with full add-on support/API 18 and a legally obtained compatible NVIDIA `nvngx_dlssnr.dll` are also required; A/B models require a recognized 310.9.16.0 runtime.
